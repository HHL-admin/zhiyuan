# 检索效果评测

对比两种检索策略在**同一份语料、同一批问题**上的表现：

- **旧方案**：按关键词重合度二选一（≥30% 只走 TF-IDF，否则只走向量检索）
- **RRF**：向量检索与 TF-IDF 各取 Top-20 候选，按 `Σ 1/(60 + rank)` 融合，取 Top-4

```bash
cd backend
python benchmark/run_benchmark.py     # 结果同时写入 benchmark/result.json
```

## 数据

| 文件 | 内容 |
|---|---|
| `corpus.json` | 42 条企业规章制度，覆盖人事、财务、IT、安全、客服、行政、项目七类 |
| `qa.json` | 44 个问题，每条标注标准答案文档 ID 与问题类型 |

**语料和问题均为人工构造**，按"关键词式提问"（29 条）和"同义改写提问"（15 条）划分。构造依据是真实企业制度文本的常见表述，但**不代表线上真实用户流量**，也不能据此推断线上效果。

指标：

- **Hit@1**：检索结果第一条是否命中标准答案
- **Hit@4**：前四条中是否命中（对应实际送入大模型的上下文条数）
- **MRR**：命中排名的倒数均值，衡量正确答案排得有多靠前

## 结果

| 方案 | Hit@1 | Hit@4 | MRR |
|---|---|---|---|
| 旧方案（二选一） | 88.6% | **100.0%** | 0.936 |
| RRF 混合检索 | **93.2%** | 97.7% | **0.955** |

按问题类型：

| 类型 | 旧方案 Hit@4 | RRF Hit@4 |
|---|---|---|
| 关键词式（n=29） | 100.0% | 100.0% |
| 同义改写（n=15） | 100.0% | 93.3% |

## 结论（含一次性能回落）

1. **排序质量提升**：RRF 把 Hit@1 提高 4.6 个百分点（88.6% → 93.2%），MRR 提高 0.019，正确答案整体排得更靠前。
2. **有一处回落**：`可以和同事讨论工资吗` 这一条，旧方案命中，RRF 未命中。原因是 `工资` 同时出现在《试用期管理》和《薪酬保密》中，前者被两路都召回（TF-IDF 第 1、向量第 2），后者只在向量检索排第 1。RRF 的累加规则天然偏向"被多路同时命中"的文档，单路第一名会被反超。**Hit@4 因此从 100% 降到 97.7%。**
3. **k 值不是原因**：k 在 5～100 之间结果完全一致，说明调节 RRF 常数解决不了这类冲突。

## 后续可做的改进（未启用）

- **加权 RRF**：把关键词一路权重降到 0.5，评测集上 Hit@1 可到 95.5%、Hit@4 回到 97.7%。但 44 条问题同时用于调参和评估，存在过拟合，**因此线上仍保持等权**；要验证需要另建一份不参与调参的测试集。
- **reranker 精排**：对融合后的 Top-20 用 bge-reranker 重排，是解决"多路命中但语义不对"的正规做法。
- **查询词处理**：过滤"可以、和、吗"这类虚词后再做 TF-IDF，可减少无关文档的关键词命中。

## 实现说明

- 每次运行使用临时目录建向量库，不改动 `data/` 下的数据。
- 两路候选都先在 `organization_id`（公司）层面过滤，评测只覆盖同一家公司内的检索质量，隔离逻辑由 `tests/test_permissions_e2e.py` 单独验证。
